# P-001 — Product strategy: an app to erase your online presence

Status: Proposal · Owner: enkeli · Created: 2026-08-14

## Goal

Turn the current copy-paste console script into an easily available app so anyone
can erase their online presence — starting with Facebook, expanding to other networks.

## Current state

- Single file `src/index.js`: UI automation against the Facebook **mobile web** DOM.
- Flow: click post menu → archive (preferred) or hide → repeat, nested `setTimeout`.
- Distribution today: paste into DevTools console with device emulation. No packaging.

## Rejected: iframe web app (original idea)

Hosting a page that embeds Facebook in an `<iframe>` and injects the script there is
**not viable**:

1. **No embed** — Facebook sends `X-Frame-Options` / CSP `frame-ancestors`; it will not render in an iframe.
2. **No cross-origin injection** — even if it loaded, same-origin policy blocks reading the FB DOM or injecting JS from your page.
3. **Trust/abuse shape** — "log in on our page, we run scripts" looks like credential phishing to users, browsers, and stores.

Web apps can still help as **docs / onboarding / download hub** — never as the place where the FB login happens.

## Architecture insight

Separate two layers:

| Layer | Job |
|-------|-----|
| **Shell** | Network picker, onboarding, progress/UX, branding |
| **Runner** | Privileged code that can touch the real site's DOM in a privileged context |

Login must always happen on the real site's origin, never on ours.

## Options matrix

| Option | What | Pros | Cons | Fit |
|--------|------|------|------|-----|
| A. Polish console script | Better README, copy button, bookmarklet | Zero install, honest, matches today | Scary for non-devs, easy to break | Short-term / fallback |
| B. Browser extension | Content script on facebook.com, user logs in to FB | Legit privileged access, store discoverability, UI | MV3 limits, store review, FB DOM breaks, ToS risk | **Best default (desktop)** |
| C. Userscript (Tampermonkey) | `@match *.facebook.com/*` | Faster than extension, big audience, easy updates | Needs Tampermonkey, less app-like | Fast middle path |
| D. Desktop app (Tauri/Electron) | Own browser, user logs in, app drives it | Rich UX, local session, multi-network RPA later | Heavy install, signing/updates, sensitive look | Branded product, not MVP |
| E. CLI / Playwright | `npx` runner, real browser | Testable, versionable, dev-friendly | Node barrier, not for normies | Advanced users |
| F. Native mobile app | Automate FB app/mobile web | Where users live | Store bans, accessibility-service bans, breaks constantly, high effort | Poor MVP |
| G. Guided-exit web product | Marketing + official Delete/Download checklists | Cleanest legally, builds trust, multi-network | No automation | **Best shell/brand** |
| H. Official APIs | OAuth + Graph API | Stable where available | FB gutted post-wipe powers, app review | Supplement, not core |

## Comparison

| Option | Ease | Feasibility | Trust | Multi-network | Effort |
|--------|------|-------------|-------|---------------|--------|
| A Console | Low | High | High | Weak | Low |
| B Extension | High (desktop) | High | High | Good | Medium |
| C Userscript | Medium | High | High | Good | Low–med |
| D Desktop | Medium | High | Medium | Excellent | High |
| E CLI | Low | High | High | Excellent | Medium |
| F Mobile | High in theory | Low in practice | Low | Hard | Very high |
| G Guide site | High | High | Highest | Content-only | Low |
| H API | Medium | Low for wipe | Highest | Per-API | High |

Original iframe idea: feasibility blocked, trust toxic — not viable.

## Recommended direction

MVP scope (decided): **multi-network shell, Facebook first**. Distribution not locked.

1. **Shell**: multi-network UI listing networks; only FB wired in v1.
2. **Runner candidates, ranked**: extension (B) → userscript (C) → console fallback (A).
3. **Desktop site (G)** as the front door: privacy statement ("we never see your password"),
   official FB Delete/Download links, and download/install for the runner.
4. **Avoid native mobile MVP**; later, optional mobile *guides* (official flows) instead of automation.
5. **Phasing**: trust/docs → FB runner → harden (selectors, backoff, pause/resume, progress) → next network.

## Open decisions

- Primary runner (extension vs userscript vs console polish) — needed before implementation.
- Mobile posture for v1.
- Scope: archive/hide timeline only, vs. plus official account-deletion checklist.
- Open-source tool vs hosted brand (affects listing, updates, liability tone).

## Out of scope for P-001

- Implementation tasks, selector work, store listing copy, packaging details.
